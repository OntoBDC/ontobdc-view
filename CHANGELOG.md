## v0.4.0

### Added

- Added the FileSizeTile component for compact human-readable storage summaries.
- Added support for terminal-only logo tiles alongside browser surface components.

### Changed

- Split RDF surface-definition adapters from browser rendering adapters.
- Restored the default presentation layout and relocated internationalization resources into the presentation package.
- Refined surface packaging, component matching, and viewport layout behavior.

### Fixed

- Corrected surface layout behavior across changing viewport sizes and restored the packaged default layout.

## v0.3.1

### Fixed

- `default_surface_layouts()` (and therefore `infobim view`/any command that resolves the operational Surface with no `view.surfaceLayoutsPath` configured) crashed with `FileNotFoundError: ... default_surface_layouts.ttl` — the packaged asset the function reads via `importlib.resources` didn't exist. It was accidentally deleted by an unrelated commit (`7bde42397b6348e5d0a574be3f66887dda9e7504`, "use official linkset directory instead of forbidden relation folder for WorkStream resource linksets"), which never touched this file's own logic but removed it from the tree anyway. Restored verbatim from the commit that introduced it (`1c55ad0`); the package's own `test_default_surface_layouts_ships_an_always_matching_fallback` test — which already asserted on this exact file — was failing locally the whole time, confirming this wasn't a packaging-config gap but a genuine missing source file. Verified the restored `.ttl` is included in a built wheel via `importlib.resources`.

## Unreleased — v0.3

### Added

- Added the Presentation Surface web component (`onto-presentation-surface.js`): a closed-shadow-DOM grid host for Tiles, reading `rows`/`columns`/`min-rows`/`max-rows`/`min-columns`/`max-columns` attributes fresh on every layout pass. Public API: `present()`, `dismiss()`, `bringToFront()` (prepend), `sendToEnd()` (append), `close()` (hide via `data-tile-closed` without removing from the DOM), `relayout()` (re-run layout without moving or hiding anything).
- Added Tile components for each auto-matched entity type: `onto-data-container-tile`, `onto-file-tree-tile`, `onto-image-file-tile`, `onto-pdf-file-tile`, `onto-csv-file-tile`, `onto-generic-file-tile`, `onto-workstream-tile`, plus `onto-logo-tile`, `onto-theme-tile`, `onto-language-tile`, `onto-photo-tile`. All read entity data from an embedded `<script id="ontobdc-surface-jsonld">` JSON-LD blob and inherit `--onto-surface-*`/`--onto-theme-*` CSS custom properties through the flat tree into slotted light-DOM children.
- Added the WorkStream Tile's expand/collapse interaction: an expand icon-button floats the Tile to the end of the occupied Surface area (scrolling with it), grows it downward to show every populated `FacadeField` without clipping content, and swaps to a collapse button that returns the Tile to its original size (not position). A separate open button links to the WorkStream's own published page (`.__ontobdc__/view/work_stream/{identifier}.html`, generated by the `ontobdc` package's `EntityViewsPublishedCapability`) in a new tab, matching the file Tiles' `open-link` convention rather than the native Fullscreen API. (Originally wired to a `DatasetViewsGeneratedCapability` that turned out to be dead code that could never have run — the link went nowhere until this session's generic entity-view-page mechanism replaced it; see the `ontobdc` package's changelog.)
- Added the `page/` plugin category (`ontobdc_view.page.plugin`), mirroring `component/plugin/`: a `WorkStreamViewPage` (`PagePort`) descriptor plus `render_entity_view()`, the public entry point `ontobdc`'s `EntityViewsPublishedCapability` calls per entity — returns rendered HTML for a matched entity type or `None`, so the mechanism stays generic across entity types with zero extra `ontobdc` code.
- Added the WorkStream 5W2H detail page itself (`page/asset/work_stream_view.{html.j2,css,js}`), matching the Tile's dark/mint visual identity exactly rather than reskinning: 7 independent per-dimension cards (What/Why/Who/Where/When/How/HowMuch), each with its own Related/Found resource tree, live preview pane, and relate/unrelate editing.
- Added live resource↔dimension relation editing via pyodide (lazy-loaded from a pinned CDN URL on first use) + `micropip`-installed `rdflib`: a Python snippet adds/removes ISO 21597 `ls:DirectedBinaryLink` triples (`ls:hasFromLinkElement`/`hasToLinkElement`, dimension URI → resource URI) in a per-WorkStream relation file (`.__ontobdc__/relation/work_stream/<identifier>.ttl`). The page's core render — 5W2H fields, resource tree, preview, annotations — works fully offline; only relate/unrelate needs the network, and only on first use.
- Wired the WorkStream page up to the (previously fully-built but never-hosted) annotation runtime shipped in `ontobdc`'s packaged assets: folder connect via the File System Access API (`showDirectoryPicker`, with the handle persisted in IndexedDB so later visits are a one-click "Allow" instead of a re-pick), an inline-annotations view/create icon pair per dimension card (view opens a tile listing that resource's annotations below the active card; create opens the full annotation editor), and "Workspace"/"Subjects" header buttons opening every annotation across the WorkStream.
- Annotations save into the dataset's own `payload/triple/EnrichmentAnnotation.ttl` (folder name derived from the WorkStream's own URI), not a container-wide `.__ontobdc__/dataset/` bucket unrelated to any specific dataset.
- The WorkStream Tile now only renders `FacadeField`s that actually have a value — fields with no data are omitted instead of showing an empty label. When a WorkStream has zero populated fields, the expand button is disabled (`title="No details to show"`) instead of growing the Tile to display nothing.
- Added touch support to the file tree Tile: `touch-action: manipulation` plus manual `touchend`-based double-tap detection (with `preventDefault()`) so opening a file works on mobile, where native `dblclick` is unreliable and the OS otherwise intercepts a fast double-tap as a zoom gesture.
- Made `onto-presentation-surface` ontology-driven: a `SurfaceDefinition`/`RegionDefinition`/`ComponentPlacementDefinition` model plus an rdflib parser (`component/adapter/surface_definition.py`) turn a `view:PresentationSurface` RDF graph into the JSON the element's new `surfaceDefinition` property consumes, replacing the previously-hardcoded three-region (operation/content/pinned) DOM topology with one materialized from the RDF model's declared regions, geometry, scrollability, and `ComponentPlacement` order/alignment. No `surfaceDefinition` set is the one explicit backward-compatibility fallback, byte-for-byte the previous fixed-topology behavior.
- Added `view:DefaultSurfaceLayout` support: `parse_default_surface_layouts()`/`default_surface_layouts()` (the latter a shipped fallback candidate — Logo/Language/Theme, no capacity bounds, always matches) plus a `defaultSurfaceLayouts` element property and a capacity-based selector (`surface_layout_selection.py`, ported 1:1 into the JS renderer so every renderer measuring the same logical capacity picks the same candidate) that measures logical column/row capacity from the same `slotTarget`/`gap`/`padding` formula the Tile-allocation grid already used, re-selecting only when measured capacity actually crosses a declared boundary, not on every resize. An explicit `surfaceDefinition` always wins over any default candidate (see `ontobdc`'s changelog for the server-side `SURFACE_OPERATIONAL_MATCHED` state that resolves and embeds these).
- A `DefaultSurfaceLayout`/explicit-surface switch (resize crossing a capacity boundary, or `surfaceDefinition`/`defaultSurfaceLayouts` changing) now migrates existing Tiles to the new topology by role (Operation/Content/Pinned) instead of rebuilding from scratch — preserving element identity, pin state, closed/open state, and ContentRegion recency order across the switch. Dispatches `surface-default-layout-changed` (previous/new layout IRI, available columns/rows).
- Bounded regions (Operation/Pinned) are now real single-row flex "toolbars" with push-to-edge alignment: a declared `EndAlignment` `ComponentPlacement` now actually sits at the far edge (an auto margin inserted at each alignment-group boundary) instead of only affecting relative order within the row.
- Added Playwright browser-level test coverage (`test/test_surface_browser.py`) for the above — closed shadow roots are exercised via a `Element.prototype.attachShadow` override applied within the page's own module script, since no prior Playwright/CDP precedent existed in this monorepo to follow.

### Fixed

- File viewer Tiles no longer appear (and occupy layout space) on initial page load — they stay closed (`data-tile-closed`) until their file is opened from the file tree, via `ComponentMetadata.default_closed`.
- WorkStream Tiles no longer auto-place ahead of the container/file-tree Tiles; Surface auto-match order is now deterministic (container, file tree, then the rest — see the `ontobdc` package's changelog for the server-side fix).
- Fixed the WorkStream Tile's collapse not actually shrinking back to size: `Node.append()`/`insertBefore()` (used by `sendToEnd()` during expand) fires `disconnectedCallback` then `connectedCallback` even when an element only moves within the same parent, which was re-capturing the already-expanded size as "original" mid-interaction. The original size is now captured once, guarded by a null check in `connectedCallback`.
- Fixed the resource lists in the WorkStream detail page rendering as a flat list instead of a real expandable folder/file tree.
- Fixed the create/view-annotation buttons being permanently disabled: `updateAnnotateButton()` gated readiness on `annotationRuntime` already being non-null, but that variable is only ever assigned lazily inside `annotateResource()`/`openWorkspace()`/`openSubjectPage()` — nothing created it proactively on folder connect. A disabled button swallows clicks with no feedback, so this deadlocked the buttons unless the user happened to open Workspace or Subjects first. Readiness now only requires the folder being connected.
- Fixed the "Workspace"/"Subjects" popups rendering unreadable, near-invisible text: they host the same `OntoBDCAnnotationWorkspace`/`SubjectPage` components used inside the (correctly dark-themed) annotation editor dialog, whose CSS hardcodes light-on-dark text — with no dark host here, that fell back to near-white text on this popup's light theme. Matched this popup's theme to the editor dialog's instead of overriding every ontobdc annotation-component color locally.
- Fixed the Workspace popup's layout (large dead space next to the legend, an unstyled browser-default "Open" button): `.ontobdc-annotation-workspace` is a genuine class-name collision between the editor's own internal image+form grid and the standalone Workspace popup's unrelated root section in the shared `ontobdc` asset. Scoped the editor's grid rule to `.ontobdc-annotation-dialog > .ontobdc-annotation-workspace` and gave the popup its own natural top-to-bottom layout plus real styling for its list/detail/buttons.
- Fixed an icon-only button (create-annotation) losing its icon permanently after first use: its loading/error feedback set `button.textContent`/`.innerHTML` on a button that only ever contained an `<svg>`, wiping the icon out of the "original content" being restored. Feedback is now conveyed via `disabled`/`title` only.
- Fixed a `SurfaceDefinition`/`DefaultSurfaceLayout` that declares regions/roles but no `columnCount`/`rowCount` geometry collapsing the surface into a 1×1 grid, where a single stretchy `1fr` row swallowed the whole Surface height behind whichever region happened to be auto-placed into it (visible as a large empty gap above the content). Falls back to ordering rows by region role instead when no explicit geometry is declared — `auto` (sized to content) for bounded regions, flexible for ContentRegion — matching the legacy stack's shape for any region set, not just the hardcoded three.
- Fixed several Tiles (e.g. `onto-logo-tile`) losing their height in bounded regions after the flex conversion above — they size themselves relative to being *stretched* by their container, and `align-items: start` doesn't stretch; bounded regions now use `align-items: stretch` (flex's own default).
- `onto-workstream-tile`'s "open" link no longer opens the WorkStream detail page in a new tab (same-tab navigation now), and carries the active theme via `?theme=` so the detail page — a separate document with no other way to know what was active on the Surface — opens in the same theme instead of always resetting to light. `onto-theme-tile` now also accepts `?theme=` as an initial-value fallback, and the detail page's "back to Surface" link round-trips it, so navigating back preserves the theme too.
- `onto-workstream-tile` now shows its Description always, in its own full-width line below the identifier, instead of only on expand alongside the rest of the 5W2H fields. `WorkStreamTileComponent`'s `min_rows`/`max_rows` bumped from 2 to 3 so this taller default content fits without being clipped by the Tile's `overflow: hidden`.
- The WorkStream detail page header's Description field only occupied its `.fields` grid's first `minmax(220px, 1fr)` auto-fill column track instead of the full tile width — that grid was sized for several short fields side by side, but only ever holds the one prose Description value. Each `.field` now spans every column track (`grid-column: 1 / -1`).

### Changed

- Moved the Tile `ComponentPort` descriptors here from the `ontobdc` package (`view.plugin.component` → `ontobdc_view.component.plugin`), and moved this package's own JS/CSS assets from `assets/components/` to `component/asset/`, aligning both under a shared `component/` root with singular naming throughout (`component`, `plugin`, `asset` — no plural segments). `__init__.py`'s `asset_root()`/`component_path()` and `build.py`'s template loader were updated to match. `ontobdc` was added as a declared dependency of this package, since the moved descriptors import `ontobdc.shared`/`ontobdc.storage`.
- Replaced the single "Annotate" button on each dimension card with an inline-annotations view/create icon pair: view opens a tile listing that resource's annotations directly below the active dimension card; create opens the existing annotation editor. Buttons now sit immediately next to their label instead of being spread across the card via `space-between`.
- Each dimension card is now full width (was a fixed narrower width), matching the surrounding Tile's own width convention.
- Toned down the geometry drag handle from a solid accent-cyan disc (which read as a second, competing marker) to a muted, translucent grey ring layered over the actual marker.
- Replaced the "Saved" feedback on the annotation editor's Save button (previously a button-text change, easy to miss) with a visible animated toast.
- `_read_component_sources()` (in `ontobdc`'s `surface_packaged.py`) now calls this package's `component_source(tag)` through the new `ComponentSourcePort` (see `ontobdc`'s changelog) instead of `ontobdc` doing its own hardcoded builder-name lookup into this package.
- Removed the `ontobdc` runtime dependency declaration from `pyproject.toml`. `ontobdc` already imports this package dynamically at runtime without a formal pip dependency in that direction (`ComponentLoader._load_ontobdc_view_components`, `SurfacePackagedCapability`); this package no longer declares one back, either — the two are still expected to be co-installed, just not coupled via a formal dependency edge in either `pyproject.toml`.

### Known gaps

- This package is not yet published to PyPI. `ontobdc` imports it at runtime for Tile discovery (`ontobdc.shared.adapter.loader.ComponentLoader`) but does not declare it as a dependency — see the `ontobdc` package's changelog. Publishing this package and declaring the dependency for real is a prerequisite before Tiles can be relied on in a packaged `ontobdc` release.
